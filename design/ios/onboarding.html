Первый запуск. По одному шагу.

Интерактивный дизайн-концепт, не новая версия приложения. Данные демонстрационные; подключения, входа и доступа к фотографиям здесь нет.

Сначала — работающий вход

  1. Ввести адрес сервера.
  2. Проверить API, сертификат и адрес входа. Подтвердить доверие.
  3. Войти существующим аккаунтом в системном браузере.
  4. Выбрать библиотеку и режим работы.
  5. Разрешить фото только для резервного копирования.
  6. Перейти в медиатеку.

«Только просмотр» пропускает запрос доступа к Фото. Пользователь, которому дали общий доступ, не обязан загружать свои снимки.

Проверить сценарий

Эти переключатели — инструменты просмотра макета. В приложении их не будет.

Никакой саморегистрации

Администратор создаёт пользователя. Apple Account для подписи приложения — не аккаунт Nephos.

Не скрывать проблемы

Недоступный issuer блокирует вход до открытия браузера. Недоверенный сертификат нельзя «просто пропустить».

Ничего не удалять

Онбординг не включает очистку Photos. Резервное копирование и удаление — разные решения.

Основной маршрут

Форма адреса → подтверждение сервера → вход → библиотека → необязательное резервное копирование. Назад можно вернуться без повторного ввода адреса. Пароли и Face ID обрабатывает системное окно, а не собственная форма приложения.

Ошибка объясняет, что делать дальше

Не один общий alert «Could not connect to the server», а отдельные состояния подключения. Технические значения доступны по раскрытию; адрес сервера и адрес входа не скрываются.

Решения для реализации

Рассмотрены: единая форма, короткий мастер, подробный мастер, старт из приглашения, QR-настройка и автоматический поиск в сети. Для первой версии выбран короткий мастер с ручным HTTPS-адресом: он не требует новых QR/Bonjour API и даёт понятные ошибки. Приглашения и обнаружение сервера можно добавить позже, не меняя дальнейшие шаги.

Разрешение локальной сети запрашивает iOS при реальной проверке сервера. При отказе экран ведёт в настройки iPhone, а не обещает определить причину любого сетевого сбоя. Для нескольких библиотек показывается выбор; общая библиотека доступна только для просмотра. Настройки бэкапа сохраняются только после явного согласия. Истёкшая сессия возвращает к входу, не сбрасывая сервер; смена сервера требует повторного подтверждения и сохраняет изоляцию данных аккаунтов.

Подтверждённый сервер и выбранный режим следует сохранять между запусками. Отменённый вход остаётся на шаге входа. Ограниченный доступ к Фото — нормальный режим, не ошибка. Недоверенный сертификат и первый вход пользователя требуют действий владельца устройства/администратора: визард помогает, но не обходит их.
